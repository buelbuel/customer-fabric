# PostgreSQL container baseline findings

Reviewed 2026-11-06. This appendix records all 61 findings from the Linux ARM64 PostgreSQL image used by the M0 security gate. The deployment pin was `postgres:18-alpine@sha256:123b17998ccaf47e53b502e8c6a1e79afd8f579c6f3eec83c563da026f957395`. Its ARM64 manifest was `sha256:c935aff069a7bbe5c286411a08e9678850d79be7848b190a0e4637b266478626`, and its image ID was `sha256:bc06ed2188a33388c6952bc58b9ce06dac389bbded2d70101c7c138218900f2f`. The image runs PostgreSQL 18.6 on Alpine 3.24.4. The baseline scanner was `aquasec/trivy:0.76.1@sha256:790fd66d1697395d8693d1acaa1ea702406a20f109b6fc7bac8db623eca6c06c`. Its raw report came from the archived scan used for the [M0 finding inventory](image-scan-2026-11-06.json).

All 61 findings targeted the bundled `/usr/local/bin/gosu` binary. Trivy reported 59 against the Go standard library build version, one against the Moby user parser and one against `golang.org/x/sys`. The Alpine package scan reported zero. These 61 findings therefore originate in the bundled helper and its dependencies. PostgreSQL 18.6 was built from source in the Alpine image, so the lack of an Alpine package finding does not assess the PostgreSQL engine on its own. The upstream PostgreSQL 18 list identifies 18.6 as the fixed version for its newest entries as of this review. [Official image Dockerfile](https://raw.githubusercontent.com/docker-library/postgres/master/18/alpine3.24/Dockerfile) · [PostgreSQL 18 security advisories](https://www.postgresql.org/support/security/18/)

The baseline binary was gosu 1.19 built with Go 1.24.6 and its SHA-256 was `3a8ef022d82c0bc4a98bcb144e77da714c25fcfa64dccc57f6aba7ae47ff1a44`. The archive shows it installed as root-owned mode 0755. At root startup the entrypoint calls `exec gosu postgres "$BASH_SOURCE" "$@"`. Gosu resolves that account, sets groups and user IDs, and replaces its own process with the entrypoint under the selected account. PostgreSQL handles database traffic after that privilege drop. The Compose database has no host port mapping. The project volume is mounted at `/var/lib/postgresql`, leaving the image's root-owned mode 0644 `/etc/passwd` and `/etc/group` outside that mount. [PostgreSQL entrypoint](https://github.com/docker-library/postgres/blob/master/docker-entrypoint.sh) · [Gosu 1.19 main](https://raw.githubusercontent.com/tianon/gosu/1.19/main.go) · [Gosu 1.19 user setup](https://raw.githubusercontent.com/tianon/gosu/1.19/setup-user.go)

Inspection of the archived ARM64 ELF Go function-name table found 2,011 function entries. It contained Moby user functions including `ParsePasswdFilter`, `ParseGroupFilter` and `GetExecUserPath`. It contained no entries for the affected network, TLS, certificate, template, archive, MIME, XML, ASN.1, PEM, Windows or scoped filesystem APIs. The table below combines this static evidence, source behavior and deployment inputs. The applicability assessments are specific to this binary and entrypoint. Trivy's original severities are preserved.

Every finding lists an upstream fixed version. For `stdlib`, these are Go toolchain versions and remediation requires a rebuilt helper binary. For modules, remediation requires a helper built against a patched dependency. A dash after a severity means the raw scan omitted `SeveritySource`. It does not replace the separately recorded advisory source. Go entries link to the Go Vulnerability Database and the Moby entry links to the maintainer's GitHub security advisory.
